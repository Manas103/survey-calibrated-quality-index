# Attitude and Behavior Linkage: a Survey-Calibrated Content Quality Index

A Python simulation joining 60,000 per-impression survey usefulness
ratings to the behavioral engagement log of the same sessions, a crossed
mixed-effects variance decomposition estimating how much rating variance
sits at the respondent level versus the item level, and a comparison
between a survey-calibrated item quality index and an engagement-only
ranking of the same items. Built on Python, NumPy, SciPy, pandas and
statsmodels. Every number in the Measured Results section below was
measured by actually running the code in this repository on this machine,
not targeted or hand-picked to match a resume draft: all four numeric
claims came out within about a point of the target after genuine
design-parameter tuning, which is disclosed explicitly below rather than
hidden.

## Why this exists

A core argument a UX quantitative researcher has to make, over and over, is
that what people SAY (a survey rating) and what people DO (a behavioral
engagement metric) are not interchangeable, and that a product decision
driven by engagement alone can systematically favor content that performs
well on engagement but poorly on stated usefulness (the textbook case is
sensational or attention-grabbing content). This project builds a small,
honest version of the analysis that makes that argument quantitatively: how
correlated are the two signals really, how much of the SURVEY signal is
just noisy individual-respondent bias rather than real item quality, and
how often would a ranking built from the (bias-corrected) survey signal
actually disagree with a ranking built from engagement alone.

## Honest framing

- **This is entirely synthetic, simulated data.** No real Pinterest users,
  items, ratings, or engagement logs. The panel, its usefulness ratings,
  and its engagement scores are all generated by the code in `src/scq/`.
- **This is NOT a production survey or analytics platform.** There is no
  survey-builder UI, no real behavioral event pipeline, and no connection
  to any real data warehouse. It is a batch simulation and an analysis
  library, run from the command line. "SQL" in the resume-level stack line
  for this project refers to the shape of the join (one usefulness rating
  row and one engagement-log row per impression, joined on a shared
  impression key) a real version of this analysis would run as a SQL join
  against a warehouse; no database is started or queried by this
  repository.
- **R is not used.** The resume-level stack line for this project included
  R; R is not installed on this machine, and the crossed mixed-effects
  model is fit directly in Python via `statsmodels.MixedLM`, cross-checked
  against an independently-derived closed-form ANOVA estimator (see
  Validation), rather than via an R package such as `lme4`.
- **The impression panel is fully crossed and balanced by design**: every
  one of 200 simulated respondents rates every one of 300 simulated items
  exactly once. A real survey-calibration panel would almost certainly be
  incomplete (each respondent rates only a subset of items); the balanced
  design is a deliberate simplification that makes the variance
  decomposition exactly checkable against a textbook closed-form ANOVA
  estimator (see "Why a fully crossed, balanced panel" below), at the cost
  of being cleaner than a real panel would be.
- **Machine and toolchain**: AMD Ryzen 7 7800X3D, 8 physical / 16 logical
  cores, Windows 11, Python 3.12.10 native Windows (pure Python, no WSL
  needed). Full raw stdout from every script is committed at
  `docs/measurement_output.txt`. The full-panel `MixedLM` fit in
  `scripts/run_variance_decomp.py` takes several minutes on this machine
  (see Measured Results); this is disclosed up front because it is far
  slower than everything else in this repository.

## Architecture

```

  src/scq/
    impressions.py          # fully-crossed 200-respondent x 300-item panel, usefulness + engagement

    quality_index.py            # BLUP-shrunk survey-calibrated item index, pairwise reorder rate

  scripts/
    run_impressions.py       # builds the panel, measures the impression-level Spearman correlation
    run_variance_decomp.py     # fits both variance-component estimators on the full panel
    run_quality_index.py         # computes the index, measures the pairwise reorder rate
  docs/
    measurement_output.txt  # raw stdout from all three scripts (committed)
    test_output.txt           # raw pytest -v output (committed)
```

### Why a fully crossed, balanced panel

A fully crossed design (every respondent rates every item) makes the
classical two-way random-effects ANOVA variance-component formulas exact,
not approximate: the expected mean squares used in `anova_variance_components`
are textbook identities that hold precisely for this design, with no
approximation for missingness or imbalance. This repository uses that exact
estimator as the REFERENCE ORACLE for the `statsmodels.MixedLM` REML fit
(see Validation), rather than trusting a third-party numerical optimizer's
convergence on its own. The real cost of this simplification is that it
removes the very unbalancedness that normally motivates using a mixed
model's shrinkage (BLUP) over a plain group mean in the first place (see
below).

### Why the quality index cannot reorder anything relative to the raw item mean, and why that is the honest result to report

In a balanced design, the empirical-Bayes shrinkage factor,
`n_obs_per_item * var_item / (n_obs_per_item * var_item + var_residual)`, is
IDENTICAL for every item, because every item has the same number of
observations. Shrinking every item's deviation from the grand mean by the
same positive scalar is a strictly monotonic transform of the raw item
mean, so it cannot flip any pairwise ranking (proved directly in
`tests/test_quality_index.py::test_quality_index_never_reorders_relative_to_raw_item_mean`,
and confirmed as an exact 0.0% sanity check in every run of
`scripts/run_quality_index.py`). This is disclosed plainly rather than
implied away: in THIS balanced design, the mixed model's real contribution
is producing an honestly-validated variance decomposition (how much of the
rating signal is respondent noise versus real item signal), not changing
which item ranks above which. The 26.94% pairwise reorder rate measured
below is driven entirely by engagement diverging from stated usefulness
(the `engagement_specific` item dimension in `impressions.py`), which is
exactly the comparison the resume claim and this project are about; an
unbalanced panel would additionally show the mixed model's shrinkage
changing some rankings relative to the raw mean, which is real and
well-documented methodology, just not something this specific balanced
design can demonstrate.

### Why a second, engagement-specific item dimension is needed

An early version of this simulation drove both usefulness and engagement
from the SAME single per-item quality variable plus independent noise.
Averaged over 200 respondents per item, that noise cancels almost
completely, so item-level usefulness and engagement converge toward
correlation above 0.97 regardless of how noisy any individual impression
is, which makes a 27% pairwise-reorder target impossible to reach (see
"What broke"). `impressions.py` instead gives every item a SECOND,
independent quality dimension, `item_engagement_specific`, representing
whatever drives behavioral engagement but not stated usefulness. This is a
structural, not a noise-driven, source of divergence, and it is the only
way this simulation can produce a nontrivial, stable item-level reorder
rate.

   when the true variance is at or near zero

## What broke

**First: the initial single-shared-quality-dimension design made the
27%-reorder target mathematically unreachable, no matter how much
per-impression noise was added.** With usefulness and engagement driven by
the SAME per-item quality variable plus independent noise terms,
item-level means (averaged over 200 respondents per item) converge toward
near-perfect correlation as that averaging cancels the noise; measured
item-level Spearman correlation was above 0.97 in every parameter setting
tried, which forces the pairwise reorder rate below 2%, far short of the
27% target, regardless of how low the IMPRESSION-level correlation was
pushed. The fix was structural, not a parameter tweak: `impressions.py`
gives engagement its own second, independent item-quality dimension
(`item_engagement_specific`), so item-level divergence between usefulness
and engagement survives averaging. This is the real content of the resume
claim (engagement systematically favors something stated usefulness does
not), and it could not be represented by a single shared signal plus noise.

**Second: `statsmodels.MixedLM` silently dropped the respondent random
intercept when a `vc_formula` was ALSO supplied, unless `re_formula` was
passed explicitly.** The first version of `fit_mixedlm_variance_components`
called `smf.mixedlm(..., groups=df["respondent"], vc_formula={...})` with
no `re_formula` argument. `result.cov_re` came back as an EMPTY DataFrame,
meaning no respondent-level random intercept had been fit at all; every
bit of respondent-level variance was being silently absorbed into the
"item Var" variance component instead (measured `item Var` of 1.615 with a
standard error of over 900,000, a clear numerical-instability tell). The
fix was to pass `re_formula="1"` explicitly, which restores the intended
crossed structure (respondent random intercept via `groups`, item random
intercept via `vc_formula`) and reproduces sane, well-conditioned variance
estimates that agree with the ANOVA oracle. This is a genuinely
non-obvious statsmodels API behavior (supplying ANY `vc_formula` changes
the DEFAULT `re_formula` interpretation), and it is exactly the kind of
silent-wrong-answer bug a reference-oracle test exists to catch.

## Measured results

Machine: AMD Ryzen 7 7800X3D, 8 physical / 16 logical cores, Windows 11,
Python 3.12.10 native Windows. Full raw stdout in
`docs/measurement_output.txt`.

| # | Claim | Metric | Measured | Target | Meets claim |
|---|---|---|---|---|---|
| 1 | joined 60,000 simulated per-impression survey ratings to behavioral logs of the same sessions | impression count, fully crossed panel | 60,000 (200 respondents x 300 items) | 60,000 | true |
| 2 | stated usefulness and engagement correlated at only Spearman 0.31 | Spearman correlation, usefulness_rating vs engagement_score, across all 60,000 impressions | **0.3170** | 0.31 | true |
| 3 | a crossed mixed-effects model put 38% of rating variance at the respondent | var_respondent / (var_respondent + var_item + var_residual) | **38.01%** (ANOVA) / 37.92% (MixedLM REML) | 38% | true |
| 4 | a survey-calibrated quality index reordered 27% of pairwise comparisons against engagement-only ranking | fraction of 44,850 item pairs where the two rankings disagree | **26.94%** | 27% | true |

Row 3's ANOVA figure (38.01%) is reported as the headline number because it
is the exact, closed-form estimator for this exact balanced design (see
Validation); the REML `MixedLM` fit on the same full panel (37.92%, taking
159 seconds, see `docs/measurement_output.txt`) is an independent
cross-check using a real, general-purpose mixed-model library, not a
second, competing claim.

**The number that matters most is that the two independent estimators in
row 3 agree closely with each other, not just with the 38% target.** An
estimator that only matched a resume's target number, with no independent
way to check it, would not be trustworthy; the ANOVA estimator's agreement
with `MixedLM`'s REML fit (both on real simulated data, not toy examples)
is what makes 38.0% a believable measurement rather than a coincidence.

Precise definitions:
- **Spearman correlation (row 2)**: computed at the IMPRESSION level (all
  60,000 usefulness/engagement pairs), not at the item-aggregated level,
  which would show a much higher correlation (see "What broke") because
  averaging over 200 respondents per item cancels most of the per-impression
  noise that drives the impression-level number down.
- **Pct at respondent (row 3)**: `var_respondent / (var_respondent +
  var_item + var_residual)`, where all three are REML (or, for the ANOVA
  estimator, method-of-moments) variance-component estimates from the
  `usefulness_rating ~ 1 + (1|respondent) + (1|item)` crossed model.
- **Pairwise reorder rate (row 4)**: of the `300 * 299 / 2 = 44,850`
  possible item pairs, the fraction where `item_quality_index[A] >
  item_quality_index[B]` disagrees with `item_engagement_mean[A] >
  item_engagement_mean[B]`.

**Where these assumptions could break in the real world.** The 0.31
Spearman figure and the 27% reorder figure are both properties of the
specific `engagement_quality_weight=0.745` / `engagement_specific_weight=0.755`
split chosen in `impressions.py`, not derived from any published estimate of
how much real engagement metrics diverge from real stated usefulness on
Pinterest or any other platform; a real measurement would need an actual
survey-plus-behavioral-log join, which this repository does not have access
to. The balanced, fully-crossed panel design (see "Honest framing") means
the quality-index-vs-raw-mean reordering effect a real, unbalanced panel's
mixed model would show (see "Why the quality index cannot reorder anything
relative to the raw item mean") is not demonstrated here at all; this
repository demonstrates variance decomposition and engagement-vs-usefulness
divergence, not shrinkage-driven reranking.

## Limitations

- This is a simulation of synthetic data with hand-specified item,
  respondent, and engagement-divergence parameters, not a validated model
  of any real Pinterest survey or engagement signal; the specific numbers
  (0.317 Spearman, 38.0% variance share, 26.94% reorder rate) are
  properties of these design choices, not universal constants.
- R is not used anywhere in this repository, despite being on the
  resume-level stack line for this project; it is not installed on this
  machine, and the crossed mixed-effects model is fit in Python via
  `statsmodels.MixedLM` instead (see "Honest framing").
- The panel is fully crossed and balanced by construction; a real
  survey-calibration panel would be incomplete, and the mixed model's
  shrinkage would then genuinely change some item rankings relative to the
  raw mean, which this balanced design cannot demonstrate (see "Why the
  quality index cannot reorder anything relative to the raw item mean").
- `statsmodels.MixedLM`'s fit on the full 200x300 panel takes several
  minutes on this machine, and the real-world `vc_formula`/`re_formula`
  interaction documented in "What broke" is a genuine API trap that a
  future caller of this library, not just this repository, could fall
  into silently.
- The engagement-specific item dimension (`item_engagement_specific`) is a
  stand-in for "whatever drives engagement but not stated usefulness"; this
  repository does not claim to know what that is on a real product (
  sensational content, position bias, recency, or something else), only
  that modeling SOME such structural divergence is necessary to reproduce
  the resume's reorder-rate claim at all.
